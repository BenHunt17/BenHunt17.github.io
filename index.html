About me

Hi, I’m Benjamin (I prefer Ben), a software developer. I currently contribute to the development and maintenance of an in-house enterprise platform. On the backend, I work with ASP.NET Core with MongoDB and on the frontend, I use React with TypeScript. The platform spans many domains and has a range of architectural patterns and infrastructure tooling, including:

  • Microservices architecture deployed via kubernetes.
  • CI/CD pipelines with Azure DevOps.
  • GraphQL (Using NestJS) for frontend data aggregation.
  • Orchestration-based saga pattern for cross service workflows.
  • Asynchronous communication through message queues.
  • A dedicated service for syncing data between a legacy system and the new platform.

Working on this platform has given me hands-on experience with designing scalable services and working with distributed systems. I continue to learn new things every day and improve my expertise in software development.


The reason I became a software developer was because I wanted to understand how things work. With so many tools and concepts out there, I find myself always curious to learn and grow in a variety of skills. That said, I've gravitated towards C# and the .NET ecosystem because they align naturally with my intuition.

Latest work

Aside from my job, I am currently building a prototype for a client tracking application for personal trainers to use. This is a full stack project where I am utilizing ASP.NET Core Web API and SQL Server on the backend and React with Typescript and TailwindCSS on the frontend. It is currently a work in progress with core feature still being developed.


I initially began this project as an opportunity to get hands-on with Entity Framework Core to broaden my database expertise beyond NoSQL. At the same time, I saw personal trainers online who were using spreadsheets to track their clients' progress. This got me thinking about if and how software could streamline this admin work, allowing PTs to spend more time with their clients.


One key thing I've learned is that developers need to be thoughtful when using Entity Framework Core, while its tooling is convenient, it's important to understand how the framework works in order to avoid performance and design issues.

My progression

Like many people, my interest in programming started because I wanted to make games. I found it fascinating that seemingly arbitrary code on a computer could somehow make it run a full interactive experience. This motivated me to study Computer Science at GCSE and from there I went to University and eventually become a professional programmer.


University

When I first started studying Computer Science at university, I had already been programming for a few years. However I had not yet grasped advanced concepts or developed anything noteworthy. That changed in my second year when I played a key role in managing a group software development project.

  • I gained experience with all steps of the software development cycle, from requirements analysis through to implementation.
  • I had the opportunity to design the relational database model and bring it to life in a database.
  • I learned about the MVC pattern and implemented features for an existing system.

In my final year, I had the opportunity to specialise in Artificial Intelligence. For my dissertation I compared a deep learning model and a traditional machine learning method for detecting people in video footage. This was during the peak of the pandemic, which had sparked my interest in automating indoor traffic control.

  • I split datasets and trained models on them.
  • I utilised python to apply these models to video footage.
  • I got familiar with all of the moving parts and inner workings of a convolutional neural network.

Frontend software developer

After graduating from university, I began working as a frontend software developer I was placed on a recently started project for building a replacement enterprise platform for a complex business domain.

  • By learning on the job I quickly picked up React, Typescript and GraphQL.
  • I began to take ownership for developing features that delivered real value.
  • Through regular scrum meetings and close collaboration, I came to understand that being a software developer is more than just writing code - it's about delivering meaningful outcomes for the business and its users.

Transition to full stack

Soon after starting my new job, I was exposed to C#, which I found appealing due to its clean syntax and structured concepts. I began honing my skills by developing a strategy game using Unity. However as I become more comfortable with frontend development, I found myself wanting to understand the backend better. I began teaching myself about server-side roles in software and quickly became eager to get hands-on experience with ASP.NET Core, which was used at work.


I decided to teach myself through developing a personal project. The project I came up with was an ambitious food recipe management system - A full-stack web appplication with a React UI and an ASP.Net Core Web API.

  • For the database I chose SQL Server and wrote stored procedures for every CRUD operation, which I accessed using Dapper.
  • Because I was keen to understand every detail and moving part, I did make some choices that I now view differently. For example, I implemented my own authentication endpoints (To my credit, I did properly salt and hash the passwords!) I now know that this should always be left to a third party authentication provider.
  • It taught me the importance of requirements analysis. I initially focused too much on technical details, which led to features that users wouldn’t realistically use — like having to manually input every food ingredient and its attributes.

I have since set this project to the side. Although my coding standards have come a long way since then, it was a pivotal learning experience. Links to the repositories are below.
